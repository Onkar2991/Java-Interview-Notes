		-> Enum

-> Syntax for Class:
				<AccessModfier>class<ClassName>
				{
					--------;
					--------;
				}

-> in java 50 Keywords are available and every keyword start with small letter.

-> Example for Class:
				public class Demo
				{
					--------;
					--------;
				}

-> Syntax for Interface:
					<AccessModifier>interface<InterfaceName>
					{
						----------;
						----------;
					}

-> Example for Interface:
					interface FirstInterface
					{
						---------;
						---------;
					}

-> bydefault access modifier of interface is default.

-> Syntax for Enum:
				<AccessModifier>enum<enumName>
				{
					---------;
					----------;
				}

-> Example for Enum:
				public enum Colors
				{
					---------;
					---------;
				}

-> universal constants are comes in enums.

	-> public
	-> private
	-> protected
	-> default

Compilation: [ javac program_name.java ]
------------

-> Java Compiler is going to check wheather we have written our program according to the java language syntax or not.
-> After successful compilation java Compiler will generate a .class file.
-> the generated .class file consists of bytecode instructions which are understandable only by the machine.(that machine is JVM).


Excecution:(Running):[ java program_name ] [JAVA VIRTUAL MACHINE - JVM] --> java generated .class filename.

-> if we want to run our java program we need to provide that generated .class file as an input to the JVM.
-> JVM will check wheather the bytecode instructions present in the .class file are correct or wrong if they are correct it will be              getting our output if they are wrong we will be getting an error.   

-> Note:any data type in double quote that data will be string data.

Q.How or when to pass values for the parameters/arguments for a method?
Ans: we need to pass values for the parameters for a parameterized method whenever we are calling the method.

-> Example:
		public class ClassA
		{
			void method1(int a)
			{
				System.out.println("Method1 Called");
				System.out.println("A Value is:"+a);
			}
			void method1(int a,String s)
			{
				System.out.println("Method2 Called");
				System.out.println("A Value is:"+a);
				System.out.println("S Value is:"+s);
			}
			public static void main(String args[])
			{
				ClassA aobj = new ClassA();
				aobj.method1();//error,becuase we cant pass the value in that parameterized method
				aobj.method1(50);//run successful.
				aobj.method2();//error,becuase we cant pass the value in that parameterized method
				aobj.method2("java is awesome",1000);//compile time error because of order of values we pass.
				aobj.method2(1000,"Java");//run successful.
			}
		}

Q. When the compiler will be coming back from the method to its calling method?

A. A compiler will be coming back to its calling method in one of the below situations:

	-> after executing all the statements which were present in that method.
	-> whenever the compiler came across the return statement
	-> if an exception occurs.

Understanding Java Variables:
-----------------------------
-> variables provide reserved memory location to store values.

-> variables are divided into 3 types:instance,static,local.

-------------------
instance variables:
-------------------

-> the variables which are declared inside a class, outside any method, block or a constructor are known as instance variables.
-> if instance variable and local variable having same name then the first priority will be given to local variable.
-> we can access an instance variable in two ways: by using identifier name,by using class object or instance.
-> if we are not initializing an instance variable, then jvm will automatically provides the default values of a datatypes.


-------------------
static variables:
-------------------

-> the variables which are declared inside a class with 'static' keyword and outside any method or block or a constructor.
-> use static keyword with variables,methods and block.	
-> static variables can never be LOCAL variables that means we cannot declare it inside a method.
-> the memory for the static variables are assigned at the time of class loading.	
-> static variables are initialized at the time of Class Loading.
-> we can access a static variable in three ways: by using identifier name,by using Class Object/instance or by using ClassName directly.
-> if static and local variable having same name then first priority will be given to the local variables.
-> if we are not initializing an static variable,then jvm will automatically provide default values of the datatype.

-------------------
local variables:
-------------------

-> the variables which are declared inside a method or a block or a constructor are known as Local Variables.
-> the scope of local variable is only upto that method(Scope of local variable is limited only that method).
-> for local variable jvm will not provide any default values, it is the responsibility of the programmer to initialize the local variable.
-> if we are declaring a local variable and without initialization if we are not using that local variable we will not getting any compile time error if we are using that local variable without initialization then our program will gets an compile time error. 


-> Example:
		public class ClassA
		{
			int a; //Instance Variable
			static int b=20; //Static Variable
			static int n=50;//static variable
			static int s;//default value of this variable is 0.
			int m=99;//Instance Variable
			void method1()
			{
				int c=30; //Local Variable
				int a=1000; //Local Variable
				int n=2000;
				System.out.println("Instance Variable:"+a);//0
				System.out.println("Instance Variable:"+new ClassA().a); //10
				System.out.println("Local Variable:"+c);  //30

Understanding 'Static' Keyword:
-----------------------------
-> static keyword in java is used for memory management.
-> static can be used in java in 3 ways: variable,method and block.

-----------------
Static Variables:
-----------------

-> static variables will be initialized at the time of class loading.
-> memory for the static variables will be assigned at the time of class loading not at the time runnnig.
-> there will be only one copy of static variable available for the entire program.
-> there will be only one copy of static variable.
-> we can access a static variable in 3 ways ( by using identifier name,by using class object, by using class name).
-> for final static variables jvm will not provide any default values, it is the responsibility of the programmer to initialize them.
-> final static variables 100% they should be initialized,wheater we are using it or not. otherwise we will be getting an compile time    error.

				System.out.println(count1); // 1 2 3 there will be only one copy of static variable.
			}

			{
				new ClassA();
				new ClassA();
				new ClassA();
			}
		}

Understanding switch case statement:
------------------------------------
-> unlike if-else for switch we will be having multiple possible executions.
-> upto java 1.4 version switch accpets only byte,short,int & char.
-> from java 1.5 version onwards switch started accepting their respective wrapper class also.
-> from java 1.7 version onwards switch started accepting String also.
-> in switch case writing case labels,default case & including break statement is optional.
-> if a case label value is matching with key value then that perticular case will be getting executed.
-> if we are not writing break statement from which case label got triggered with the key value, from that case onwards all the cases wil be executed.
-> default case will be executed only if no case label is matched with the key value.
-> we can write default case anywhere inside the switch, it will be getting executed if no case label is triggered.
-> duplicate case labels are not allowed in switch we will be getting an compile time error.
-> every statement present inside switch case should belong to a particular case, otherwise we will getting a compile time error.
-> case value should be within the range of key datatype.
-> expresssion are also allowed in switch.(at key and labels also)
-> key values and case labels value should be compatible.
-> in switch, case labels should be compile time constants.

-> Syntax:
		switch(key)
		{	
		case label1:
				-----;
		case label2:
				------;
		case label3:
				------;
		.
		.
		.
		default:
				------;
		}

-> Example:1:

		public class ClassA
		{
			void method1()
			{
				System.out.println("implementing switch case");
				int a = 50;
				final int x = 10;//final variables are constants.
				byte b = 40;
				switch(a-int type)or(b-byte type)or(b+10) - this will become int for compiler)//40+10=50(int)
				{
					System.out.println("Hello World");//compile time error
					case 10:
						System.out.println("case 10 got executed");
						System.out.println("a Value is"+a);	
						break;
					case 200://label value must be in range of datatype range.
						System.out.println("case 20 got executed");
						System.out.println("a Value is"+a);	
						break;	
					case 300-180://allowed
						System.out.println("case 30 got executed");
						System.out.println("a Value is"+a);	
						break;
					case x://allowed only when it declared as final variable
						System.out.println("case 40 got executed");
						System.out.println("a Value is"+a);	
						break;
					case 50:
						System.out.println("case 50 got executed");
						System.out.println("a Value is"+a);	
						break;
					case 'A'://key values and case labels value should be compatible
						System.out.println("case 60 got executed");
						System.out.println("a Value is"+a);	
						break;
					default:
						System.out.println("no case labels got triggered with key value");
				}
				System.out.println("compiler came out from the switch case");
			}
			public static void main(String args[])
			{
					new ClassA().method1();
			}
		}

-> we need to write two semicolons inside the for loop.
-> Initialization statement will be executed only for once.
-> incr/decr operator will be executed until the condition is false.
-> if the condition is false then the compiler will never execute increment/decrement opearator. 
-> we can initialize a variable outside the for loop i.e. before the loop also.
-> we can write increment or decrement operator inside the body of the for loop.
-> we can write any valid java statement in initialization and incre/decre statement.
-> in for loop we write all select statements.
-> if we provide i++ outside the for loop then their will be a compile time error because that i variable belongs to that loop only.

		for(Initialization;TestCondition;incr/decr)

Difference Between OOPs vs POPs:
---------------------------------

OOP-> OOP stands for Object Oriented Programming it is focuses on data rather than the algorithm.
POP-> POP stands for procedure oriented programming,focuses on procedural abstractions.

OOP-> Divided into small chunks called objects which are instance of Class.
POP-> Divided into small parts based on the functions.

OOP-> Four accessing modes are used in OOP to access attributes or methods-public,private,protected,default.
POP-> No such accessing mode is required

OOP-> variuos methods can work simultaneously.
POP-> follows a systematic step-by-step approach to execute functions.

OOP-> it is of high secure because of its data hiding feature.
POP-> there is no such way of data hiding in POP, thus making it less secure.

OOP-> Bottom-Up Approach
POP-> Top-Bottom Approach.

2.Inheritance:
--------------
-> Acquaring the properties of one class into another class.
-> there are two types of relationships: IS-A Relationship, HAS-A Relationship.
-> inheritance is also known as IS-A Relationship
-> in java we can achieve inheritance by using extends keywords or implements keyword.
-> Example:1: 

			package com.pack1;
			public class ClassA //Parent Class/Super Class
			{
				public void method1()
				{
					System.out.println("ClassA Method");
				}
			}


			package com.pack1;
			import java.util.Scanner;
			public class ClassB extends ClassA //Child Class/Sub Class
			{
			
				public static void main(String args[])
				{
					ClassB obj2 = new ClassB();
					//obj2.method1();//C.E // this will be solve using inheritance concept.
					obj2.method1();
					
					ClassA obj1 = new ClassA();//HAS-A Relationship
					obj1.method1();
				}
			}


Kyepoints Of Inheritance:
-------------------------

-> We can hold parent class object with parent class reference and with that reference we can call only parent class methods.

				ClassA obj = new ClassA();//only call parent class methods.

-> We can hold child class object with parent class reference and with that reference we can call only parent class methods.

				ClassA obj = new ClassB();//only call parent class methods.

-> We can hold child class object with child class reference and with that reference we can call both parent and child class methods.
			
				ClassB obj = new ClassB();//both parent and child class methods.

-> We cannot hold parent class object with child class reference we will getting an compile time error.

				ClassB obj = new ClassA();//C.E.

-> Example:2: 

			package com.pack1;
			public class ClassA //Parent Class
			{
				public void method1()
				{
					System.out.println("Parent Class Method");
				}
			}


			package com.pack1;
			public class ClassB extends ClassA //Child Class
			{
				public void method2()
				{
					System.out.println("Child Class Method");
				}
				public static void main(String args[])
				{	
					ClassA obj1 = new ClassA();//HAS-A Relationship//Holding Parent Class Object With Parent Class Reference.
					//No need to use Inheritance.
					obj1.method1();
					obj1.method2();//C.E.

					ClassA obj2 = new ClassB();//Holding Child Class Object With Parent Class Reference.
					//if we remove extends keyword from child keyword in above line we getting the error.
					obj2.method1();
					obj2.method2();//C.E.
			
					ClassB obj3 = new ClassB();//Holding Child class object with Child class reference.//IS-A Relationship
					obj3.method1();//parent class method
					obj3.method2();//child class method

					ClassB obj3 = new ClassB();// Invalid //we Cannot hold parent class object with child class reference.
					
				}
			}

2.Run Time Polymorphism(Method Overriding):
------------------------------------------
-> writing two or more methods in two different classes having same method name,same parameters and same return type.
-> Method Overriding occurs in two different classes.
-> without using inheritance we cannot achieve method overriding.
-> changing the implementation of perticular method is called overriding.
-> if we cant inherit a method(private method) we cant override that method.
-> it is also known as "late-binding" or "run time" polymorphism.
-> the method present in super class is called overridden method and the method present in sub class is called overriding method.
-> when an overridden method is called through a super class reference, java determines which version of that method is to be executed based upon the type of that object being referred to at the time of the call occurs. thus, this determination is made at run time. this is the reason it is called Run-Time Polymorphism.

Overridden Rules:
-----------------
-> the argument list must exactly match that of the overriden method.
-> the return type should exactly match that of the overriden method(upto 1.4 version)
-> after jdk 1.5 return type may not be same in co-variant return types.(co-variant types concept is applicable for object types).
-> the access level must not be more restrictive than that of the overridden method(private<default<protected<public)
-> if a method cant be inherited we cannot override it (E.g.private).
-> we cant override the constructors.

abstract method:

-> An abstract method always ends with semicolon(;).
-> For an abstract method there is no method body/method implementation/method functionality.

-> an abstract class cant be instantiated(we cant create an object for an abstract class).

-> if we dont want to provide the implementation for the abstract methods present in the abstract class then make the child class as an abstract class.

Java Interface:
---------------
-> Interface is not a class, it is a blueprint of a class.
-> Syntax:
		<AccessModifer> interface <interface_name>
		{
		
		}
-> Every method in interface is bydefault public abstract.
-> Every variable in interface is by default public,static and final.
-> from java 1.8 onwards in interface we can write static methods and default methods.
-> from java 1.8 version onwards we can write main() also inside an interface.
-> from java 1.9 version onwards in an interface we can write private method also.
-> just like abstract class we cant create object of an interface.
-> for the abstract methods present in the interface we need to provide implementation by using method overriding.
-> if we want to inherit an interface in a class we need to use "implements" keyword.
-> if we want to inherit an interface in a interace we need to use "extends" keyword.
-> interface is a mechanism to achieve fully abstraction in java.
-> we can declare a class inside the interface.

-> Example :
			ClassA ---------------> ClassB
					extends

			InterfaceA ---------------> ClassA
					   implements


			InterfaceA --------------------> InterfaceB
						extends

-> if we are inherting an interface and if there are any abstract methods present in that interface then in the child class 100% we need to provide implementation for the abstract methods present in that interface otherwise we will be getting an C.E.
-> if i dont want to provide implementation for the abstract methods present in the interface then we need to make my child class as abstract
-> by using java interfaces we can achieve multiple inheritance.
-> we cant write constructors in interface, because interface is not a class.

Deadlock:
---------
-> thread 1 is holding object 1 and thread 2 holding object 2 now in order to complete the execution of thread, thread 1 needs object 2 and in order to complete the execution of thread 2 thread 2 need object 1 but object 1 is held by thread 1, thread 1 will release this object if object 2 is available. thread 2 will release this object 2 if object 1 is available now both these threads will be contineously in waiting state forever,execution will not be completed that scenario is known as Deadlock.

-> Example:(Deadlock):

			package com.pack1;
			public class ClassA
			{
				public static void main(String args[])
				{
					final String a = "Java";
					final String b = "Python";
					
					Thread t1 = new Thread()
					{
						public void run()
						{
							synchronized(a)//Java //Thread 1 is Holding Java
							{
								System.out.println("Thread 1 Locked on a");
								try
								{
									Thread.sleep(100);
								}
								catch(Exception e)
								{
									e.printStackTrace();
								}
								//Waiting for B
								synchronized(b)
								{
									System.out.println("Thread 1 Locked on b");
								}
								System.out.println("No DeadLock");
							}
						}
					};

					Thread t1 = new Thread()
					{
						public void run()
						{
							synchronized(b)//Python //Thread 2 is Holding Python
							{
								System.out.println("Thread 2 Locked on b");
								try
								{
									Thread.sleep(100);
								}
								catch(Exception e)
								{
									e.printStackTrace();
								}
								//Waiting for A
								synchronized(a)
								{
									System.out.println("Thread 2 Locked on a");
								}
								System.out.println("No DeadLock");
							}
						}
					};
					t1.start();
					t2.start();
				}
			}

Understanding Exception Handling:
---------------------------------
-> an error in a program is called bug. Removing errors from program is called debugging. there are basically three types of errors in the java program.

Compile Time Errors:
--------------------
Errors which occurs due to syntax or format is called compile time errors. these errors are detected by java compiler at compilation time.Desk checking is solution for compile time errors.

Run Time Errors:
----------------
These are the errors that represent computer inefficieny. Insufficient memory to store data or inability of the microprocessor to execute some statement is examples to runtime errors. Runtime errors are detected by JVM at runtime.

Logical Errors:
---------------
These are the errors that occur due to bad logic in the program. these errors are rectified by comparing the outputs of the program manually.


-> if our program is having an error we cannot save our program means 100% that program will be terminated until you resolve that error.
-> if our program is having an exception and if we handle that exception program will not be terminated.

-> errors cant be handled.
-> exceptions can be handled.

Exception Handling:
-------------------
-> exception handling means not removing or resolving an exception we are providing an alternate way to continue the flow of program. after exception handling the program will not be terminated abnormally.even after exception handling mechanism is done exception will be present in your program but the program will not be terminated.

Q. how to handle an exception ?
A. We can handle an exception by using try,catch and finally block.

		try
		{
			//inside the try block we need to write the suspicious code
		}
		catch
		{
			//inside the catch block we need to handle an exception which occured in the try block.
		}
		finally
		{
			// finally block will always gets executive irrespective of the exception.
		}

-> Example:
		package com.pack1;
		import java.util.Scanner;
		public class ClassA
		{
			void method1()
			{
				Scanner sc = new Scanner(System.in);
				System.out.println(10);
				try
				{
					System.out.println("try block executed");
					System.out.println("Please Enter The number");	
					System.out.println(20/sc.nextInt());
				}
				catch(ArithmeticException ae)
				{
					System.out.println("catch block executed");
				}
				finally
				{
					System.out.println("finally block executed");
					sc.close();
				}
				System.out.println("===>"+30);
			}
			public static void main(String args[])
			{
				new ClassA().method1();
			}
		}

-> catch will be executed only if there is exception inside the try block. if there is no exception occured inside the try block then catch block will never get executed.
-> irrespective of the exception finally block will always get executed. finally block is used to close the resources and connections.

-> when there is an exception the programmer should do the following tasks:
	
	1) if the programmer suspects any exception in program statements,he should write them inside the try block.
		
			try
			{
				statements;
			}

	2) within the try block if anywhere an exception raised then rest of the try block won't excecuted even though we handled that exception. 

	3) When there is an exception in try block JVM will not terminate the program abnormally.

	4) JVM stores exception details in an exception stack and then JVM jumps into catch block.

	5) the programmer should display exception details and any message to the user in catch block.
		
			catch(ExceptionClass obj)
			{
				Statements;
			}
	
	6) Programmer should close all the files and databases by writing them inside finally block.
	
	7) finally block is executed wheather there is an exception or not.

			finally
			{
				statements;
			}

	-> Performing above tasks is called Exception Handling.

-> Example:

		package com.pack1;
		import java.util.Scanner;
		public class ClassA
		{
			void method1()
			{
				System.out.println(10);
				try
				{
					System.out.println("try block executed");	
					System.out.println(20/0);
				}
				catch(ArithmeticException ae)
				{
					System.out.println("catch block executed");
					System.out.println(ae.getMessage());// it will show why the exception will occurs.
					//getMessage()----> Throwable
					System.out.println(ae.toString());//Name of the exception along with the reason.
					//toString() -----> Throwable
					e.printStackTrace();//it will give the complete information abour exception.
				}
				finally
				{
					System.out.println("finally block executed");
				}
				System.out.println("===>"+30);
			}
			public static void main(String args[])
			{
				new ClassA().method1();
			}
		}

Understanding "final" keyword:
------------------------------
-> it is used to restrict the user.
-> we can use final in 3 ways: Variable,Method,Class.

final variable:- final variables are constants we cant change when its declared as final.
final method:- final method can't be overridden 
final class:- final classes cant be inherited.

-> private method: we cannot inherit private method so we cannot perform method overriding.
-> final method: we can inherit final method but we cannot perform method overriding.

-> Example:(final variables are constants we cant change when its declared as final).
		package com.pack1;
		public class ClassA
		{	
			int a=10;//instance variable
			final int b=20;//final variable are constants
 			void method1()
			{
				System.out.println("ClassA method1() called");
				System.out.println(a++);//10
				System.out.println(a);//11
				System.out.println(b++);compile time error because we cant change value of the final variables.
			}						
			public static void main(String args[]) throws Exception
			{
				new ClassA().method1();
			}
		}

-> Example:(final method can't be overridden)
		
		package com.pack1;
		public class ClassA
		{	
 			final void method1()//final method cant be overridden.
			{
				System.out.println("ClassA method1() called");
			}					
		}

		package com.pack1;
		public class ClassB extends ClassA
		{	
 			void method1()
			{
				System.out.println("method overridden");
			}						
			public static void main(String args[]) throws Exception
			{
				ClassA obj = new ClassA();
				obj.method1();

				ClassB obj1 = new ClassB();
				obj1.method1();
			}
		}

-> Example:(final classes cant be inherited)

 			final void method1()//final method cant be overridden.

Understaning Garbage Collector:
-------------------------------
-> it is used to destroy all the Unused or Unreferenced objects from the heap memory.
-> Garbage collector is a daemon thread it will be executing in the background of every java program. no need to call the garbage collector manually but if we want to call the garbage collector manally also we can do that with the help of System class and Runtime class.Garbage collector will use an algorithm that is mark and sweep algorithm.

Q. when an object will be eligible for garbage collection?
A. An object will be eligible for garbage collection in any of the below mentions ways:
   1.if we are nullfying the reference.
   2.if we are assigning the reference to another reference.
   3.all the objects which were created inside a method.

-> if garbage collector is acting on your program it will internally called finalized() method. finalize method will close the existing connections with that object.

->Example:
		public class ClassA
		{
			void method1()
			{
				System.out.println("method1() called");
				ClassA obj = new ClassA();//every object will be present inside method will be destroyed when u shutdown JVM.
				//(3rd Case)all the objects which were created inside a method.
			}
			protected void finalize()//this method will call only when we call gc() of System Class.
			{
				System.out.println("Garbage has been Collected");
			}
			public static void main(String args[])
			{
				ClassA obj1 = new ClassA();//first object
				ClassA obj2 = new ClassA();//second object

				obj1.method1();

				//obj1=null;//(1st Case)if we are nullfying the reference

				//obj1.method1();//raises an NullPointerException

				//obj2 = obj1;//(2nd Case)if we are assigning the reference to another reference.

				System.gc();this is a static method which is present in System class.
			}
		}

1.Byte Streams:
---------------
-> in byte streams data will be transferred in the form of bytes and the length of each data packet is of 1 byte.
-> in bytes tream there are two abstract classes are available: InputStream, OutputStream.
-> for these two abstract classes for Inputstream we have implementation class as FileInputStream and for OutputStream we have implementation class as FileOutputStream.
-> inside the FileInputStream class we have a method called read().
-> inside the FileOutputStream class we have a method called write().
-> the return type of read() is int, read() method returns the ASCII values of the characters which are present in the file. if there is no characters present in the file then read() method return -1.
-> write() method accept two type of parameters: int,byte array.
-> all IOStream Classes are presenet inside the java.io package.

-> Example:
			package com.pack1;
			import java.io.FileInputStream;
			import java.io.FileOutputStream;
			public class ClassA
			{
				void fileOperation1() throws Exception//read data from file.
				{
					FileInputStream fis = new FileInputStream("E:\\Raj\\file1.txt");	
					System.out.println("Connection Created");
					int x;
					while(x=fis.read()!=-1)
					{
						System.out.println(x);//65 66 67 68 69 70 -1(condition is false and loop will be terminated)
						System.out.println((char)x);// ABCEDEF 
					}
					System.out.println();
					System.out.println("Data Retrieved....");
					fis.close();				
				}
				void fileOperation2() throws Exception//write data into the file.
				{
					FileOutputStream fos = new FileOutputStream("E:\\Raj\\file2.txt",true);//true initiates append mode.	
					System.out.println("Connection Created");
					String data = "Java is Awesome";
					//String data = "so, I love it";this data will replace the above data if we provide in "data" variable
					byte arr[]=data.getBytes();
					fos.write(arr);
					System.out.println("Data Entered....");
					fos.close();				
				}
				void fileOperation3() throws Exception//copy data from one file to another file.
				{
					FileInputStream fis = new FileInputStream("E:\\Raj\\file2.txt");	
					FileOutputStream fos = new FileOutputStream("E:\\Raj\\file3.txt");

					{
						fos.write(x);

Understanding Buffered Streams:
-------------------------------
-> buffered streams are compatible for byte streams and character streams.
-> A buffer is a portion in the memory that is used to store a stream of data.
-> in I/O opearations each read and write request is handled directly by the underlying os.
-> this can make a program much less efficient, since each such request often triggers disk access, network activity, or some other operation that is relatively expensive.
-> to reduce this kind of overload, the java platform implemented buffered I/O streams.
-> buffered input streams read data from a memory area known as a buffer.
-> buffered output streams write data to a buffer.
-> Buffered streams are same like Byte and Character Streams but with more efficiency.

4.Object Streams:(Serialization)
--------------------------------
-> Serialization means converting a java class object into network supported format or file supported format.
-> Serialization is a process of converting java class object into network supported fromat or file supported format. in order to perform this serialization we need to use Object streams
-> in object streams we have two implementation classes i.e. ObjectInputStream And ObjectOutputStream.
-> ObjectInputStream will take source as FileInputStream.
-> ObjectOutputStream will take source as FileOutputStream.
-> for serialization process we have to implement serializable interface in class which we have to serialize otherwise it will throws an exception called NotSerializableException.

-> Example:
		package com.pack1;
		import java.io.serializable;
		public class ClassA implements Serializable
		{
			int a=10;
			int b=20;
		}
		
		package com.pack1;
		public class ClassB implements Serializable
		{
			int x=1000;
			int y=2000;
		}

		package com.pack1;
		import java.io.ObjectOutputStream;
		import java.io.FileOutputStream;
		public class ClassC
		{
			public static void main(String args[])
			{
				ClassA aobj = new ClassA();
				ClassB bobj = new ClassB();

				ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("E:\\raj\\Data.ser");
				System.out.println("Connection Created...");
				oos.writeObject(aobj);
				oos.writeObject(bobj);
				System.out.println("Serialization Completed");

				System.out.println("----------------------------------------");

				System.out.println("DeSerialization Started...");
				ObjectInputStream ois = new ObjectInputStream(new FileInputStream("E:\\raj\\Data.ser");
				ClassA aobj2 = (ClassA)ois.readObject();
				ClassB bobj2 = (ClassB)ois.readObject();
				System.out.println("DeSerialization Completed");
				
				System.out.println(aboj2.a + " " + aobj2.b);//10 20
				System.out.println(boj2.x + " " + bobj2.y);//1000 2000
			}	
		}

Collection Framework:
---------------------

-> in collection framework there are two different root interfaces are availale: Collection,Map.

-> Collection Interace:in Collection interace there are 3 child interfaces are there : List,Set,Queue

-> For List interface we have 3 implementation classes : ArrayList,LinkedList,Vector.

-> For Set interface we have 3 implementation classes : HashSet,LinkedHashSet,TreeSet.

-> For Queue interface we have 3 implementation classes : LinkedList,PriorityQueue.

-> For Map interface we have 4 implementation Classes : HashMap,LinkedHashMap,TreeMap,Hashtable.


List:
-----
-> in List interface elements will be stored just like an array. list accepts duplicate elements also.

Set:
----
-> in Set interface elements will be stored just like an array. Set will not accepts duplicate elements.

Queue:
------
-> in Queue interface elements  will be stored just like an array but in the form of FIFO (First In First Out).

Map:
----
-> in Map interface elements will be stored in the form of key value pairs.

	3.By using Iterator interface -> iterates only in forward direction.
	4.By using ListIterator Inteface -> iterates in both direction i.e forward and backward direction.

Lambda Expresssions:
-------------------
-> Lambda expression unable functional programming in java.
-> it is introduced in java 1.8 version.
-> lambda expressin does not need any access modifier, lambda expression does not need any return type and also we dont need an name for method.
-> lambda expression always end with a semicolon.
-> lambda expression or lambda function is a new feature in java 8 version.
-> lambda function is anonymous function which does not have any name.
-> lambda expression is used to write a complete new code, if you already have an method which have that code then doesnot go for lambda expression refer this method.

Defining Lambda Expression:
--------------------------
-> A lambda Function can be defined in different ways,
		-> A Lambda function without parameters
		-> A Lambda function with single parameter
		-> A Lambda function with multiple parameters
		-> A Lambda function with return statement.
		-> A Lambda function without return statement.

Difference Between Lambda Expresssion and Method:
-------------------------------------------------
-> A method in java having the following components:
			->Modifier
			->Return type
			->Method name
			->parameters
			-> body
-> A lambda expression is an anonymous function, it has the following components:
			-> without name
			-> without return type,java compiler is able interface return type based on the code, you have return
			-> parameter list
			-> body

	-> Eg:(Normal Method):

		int a=10;
		public void method1()//we want to assign this entire method to something 
		{
			System.out.println("Hello World");
		}
		 
	-> Eg:(Lambda Expresssion):
		
		int a=10;
		Something x = ()->System.out.println("Hello World");

	-> Eg:(Normal Method):

		public void method2(int a,int b)
		{
			System.out.println("Addition:"+(a+b));
		}
		 
	-> Eg:(Lambda Expresssion):
	
		Something x = (int a,int b)->System.out.println("Addition:"+(a+b));


	-> Eg:(Normal Method):

		public void method3(int m,int n)
		{
			if(m<10)
				return m+10;
			else
				return n+20;
		}
		 
	-> Eg:(Lambda Expresssion):
	
		Something x = (int m,int n)->{
									if(m<10)
										return m+10;
									else
										return n+20;
								};

-> lambda expression is assign to a functional interface.
-> lambda expresssion is not compatible with abstract method which is present in your interface.
-> if we are having two then also because compiler doesnot know this lambda expression is checking with which method for that only if we want to use lambda expression u need to have a functinal interface.

-> Example:

	2.Static method referencing.
	3.constructor referencing.

Inner Classes:
--------------
-> inner classes are defined inside the body of a another java class.
-> for inner classes we can use all the four access modifiers.
-> even can be marked as abstract and final.
-> inner classes have special relationship with outerclass instances, which allows them to have access to outer class memebers including private members also.
-> Inner classes are used to access the private members of the outer class.
-> Java provides four type of inner classes:
			1.nested inner class.
			2.static inner class.
			3.method local inner class.
			4.anonymous inner class.

-> We can write main() inside the Inner class only if it is static inner class.

Nested InnerClass:
------------------
-> as the name suggests, this type of inner class involves the nesting of a class inside another class.
-> the inner class can access the private variables of the outer class.
-> we can modify access to the inner class by using access modifier keywords such as private,protected and default.

			{
				void method2()
				{
					System.out.println("I am from inner class");
					System.out.println("We can use all the 4 access modifiers for the Inner Classse");
					method1();
				}
				InnerClass()
				{
					System.out.println("default constructor of inner class");
				}
				
			}
			public static void main(String args[])
			{
				ClassA.InnerClass obj = new ClassA().new InnerClass();
				obj.method2();
			}

-------
-> flow of data or objects is known as stream.

Stream API : means working with flow of objects.

-> Stream API is used to process collection of objects.
-> a Stream is a sequence of objects that supprts various methods which can be pipilined to produce the desired result.

Basic types of objects holding data:

							2.Wrapper class objects
							3.String objects.

Features:
---------
-> A stream is not a data structure instead it takes input from the Collections, Arrays or I/O Channels.
-> Streams dont change the original data structure,they only provide the result as per the pipelined methods.

Operations on Stream:
--------------------
-> we can perform following two types of operations on streams:1.Intermediate Operations 2.Terminal Operations

1.Intermediate Opearations: The Operations which are performed in between stream flow is known as intermediate operations
		
		a) map()
		b) filter()
		c) sorted()

2.Terminal Operations: The Operatiosns which are performed at the end of stream are known as Terminal Opeartions.
	
		a) collect()
		b) forEach()
		c) reduce()

map():
------ 
-> the map() is used to return a stream consisting of result of applying the given function to the elemeents.
-> Method Signature:
				public abstract <r> java.util.stream.Stream<R> map(java.util.Function<?,Super T,? extends R>);
-> Structure of Function://Function is a functional interface which have only one abstract method i.e apply().
		public interface java.util.function.Function<T,R>
		{
			public abstract R apply(T);
		}

-> Example:					
			package com.pack1;
			import java.util.*;
			import java.util.stream.*;
			public class DemoProg3_map
			{
				
				public static void main(String args[])
				{
					List<Integer> ob = List.of(2,1,6,4,5);//immutable object (we cannot modify that data)
					System.out.println("===Normal List===");
					System.out.println(ob.toString());//2 1 6 4 5 
					System.out.println("===map()===");
					Stream<Integer> sm = ob.stream();
					sm.map((x)->x*x).forEach((y)->System.out.println(y));// 4 1 36 16 25
					System.out.println("===Terminal collect()===");
					Stream<Integer> sm2 = ob.stream();
					List<Integer> lst = sm2.map((x)->x*x).collect(Collectors.toList());
					//lst.forEach((y)->System.out.println(y));//IllegalStateException if we not provide stream object
					lst.forEach((y)->System.out.println(y));
					System.out.println("===Terminal reduce()===");
					Stream<Integer> sm3 = ob.stream();
					int res = sm3.map((x)->x*x).reduce(0,(sum,i)-> sum+i);
					System.out.println("sum of elemnents:+res);
				}
			}
